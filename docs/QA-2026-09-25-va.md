## Security lane reports (fixed or answered)

- Two people assigning the same order at once: the second got a server error (the one-active-assignment
  index, Postgres 23505, confirmed locally). Now a plain toast: "Someone else assigned this order a moment
  ago. Refresh to see who has it" (`683c001`).
- `/orders/not-a-uuid` (also `/orders/<unknown uuid>`, `/orders/x/complete`, `/qc/x`, `/customers/x`): the
  person sees the app's 404 page, but the HTTP status is 200 because these pages stream behind their
  loading skeleton (docs/PERF.md), and a streamed `notFound()` cannot change a status already sent. A real
  404 status needs the check before streaming (middleware, the security lane's file) or dropping the
  skeleton (slower first paint). Left as is, reason given.
- Tour back over an order page after Skip on a phone: a Skip whose save was lost (slow or dropped request)
  left the run "started, not finished", so the next full page load resumed it. Skip and finish are now
  remembered in the tab, the resume is refused there and the save is sent again, with two retries
  (`7a2741e`).
